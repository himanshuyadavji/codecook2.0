# Patchly design brief

- Design read: A calm, premium security workspace for developers who need useful findings without sending private code to a remote service.
- Concept spine: The code workbench as a private lab. A dimensional shield signals protection; the workspace makes inspection tangible; findings turn into next steps.
- Delivery tier: spectacle-inspired interface craft using CSS depth, glass material, controlled motion and a usable security workspace. No external 3D runtime or video asset required for the interactive tool itself.
- Animation mode: non-animated — user chose to proceed with a functional scanner product; the product workspace takes priority over a scroll-controlled marketing film.
- Locked palette: #101116 background, #171820 surfaces, #D3F36B single accent, #F2F2F4 primary text, #9A9CA9 muted text. Lime is reserved for positive security states and the primary action; coral is used for risk states only.
- Locked type: Geist-like geometric sans display with system sans body and SF Mono for code.
- Signature interaction: a hovering dimensional shield in the hero, followed by a live in-browser scanner where selecting a finding updates the evidence and remediation pane.
- Section plan: asymmetric hero; horizontal trust strip; large split code workbench; three-step process; split privacy feature; centered closing CTA.
- Asset plan: original shield mark as inline SVG favicon; hero shield and workspace are built from CSS surfaces and the actual interactive scanner, not a fake static screenshot. Report and code content are real application state.
- CTA inventory: “Scan code” in navigation, “Start a free scan” in hero, “Run security scan” in the workspace, “Scan your code” in privacy section, “Run your first scan” in closing CTA.
- Functionality: browser-local source code text/file reading; deterministic security pattern rules; finding details, CWE references, severity filters, remediation guidance, JSON report export, sample project, responsive navigation, accessible controls, reduced-motion support.
- Trust boundary: never execute uploaded code. Never upload source files. State clearly that pattern scanning is not a full security audit and can produce false positives or miss vulnerabilities.
